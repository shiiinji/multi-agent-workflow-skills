# shin-qa-design

QA観点からテスト戦略を総合的に設計するワークフロー。

## 概要

| 項目 | 内容 |
|------|------|
| 対象ツール | Claude Code / Codex |
| 用途 | テスト戦略の設計（Unit/Integration/E2E） |
| 入力 | 計画書ファイル |
| 出力 | テスト設計書ファイル |

## 位置づけ

```
planner-workflow → qa-design-workflow → tdd-workflow / execute-workflow
                        ↑
                      今ここ
```

tdd-workflow が「テストを書いて実装する」実行フェーズなのに対し、qa-design-workflow は「何をどうテストするか」を設計する計画フェーズ。

## ワークフロー

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ Plan Reader │ ──▶ │  Analyzer   │ ──▶ │  Designer   │ ──▶ │   Review    │
│ (計画読込)   │     │ (リスク分析) │     │ (テスト設計) │     │ (外部レビュー) │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

## テスト設計の3レイヤー

| レイヤー | 対象 | 観点 |
|----------|------|------|
| **Unit** | 関数/クラス | ロジック、境界値、エッジケース |
| **Integration** | モジュール間 | API、DB操作、外部サービス連携 |
| **E2E** | ユーザーシナリオ | 画面遷移、クリティカルパス |

## 使用例

```bash
# 1. 計画を立てる
/shin-planner ユーザー認証機能を追加したい

# 2. テスト設計を行う
/shin-qa-design ./docs/{topic}/plan.md

# 3. TDD で実装（テスト設計書を参照）
/shin-tdd ./docs/{topic}/plan.md
```

## 出力: テスト設計書

```markdown
# テスト設計書

## リスク分析
- 高リスク: [必須テスト]
- 中リスク: [推奨テスト]
- 低リスク: [任意テスト]

## Unit Test 設計
| テストケース | 入力 | 期待出力 | 優先度 |
|-------------|------|---------|--------|
| 正常系 | ... | ... | 高 |

## Integration Test 設計
| シナリオ | 前提条件 | 操作 | 期待結果 |
|---------|---------|------|---------|
| API呼び出し | ... | ... | ... |

## E2E Test 設計
| シナリオ | ステップ | 期待結果 |
|---------|---------|---------|
| ログインフロー | 1. ... 2. ... | ... |
```

## tdd-workflow との連携

qa-design-workflow で作成したテスト設計書を、tdd-workflow の Test Writer フェーズで参照する：

```
qa-design-workflow
    │
    │ テスト設計書（何をテストするか）
    ▼
tdd-workflow
    │
    │ Test Writer（設計書を元にテストコード作成）
    │ Implementer（テストが通る実装）
    ▼
  完了
```
