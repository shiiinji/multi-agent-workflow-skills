# shin-planner

指示→計画→外部レビュー→改善の4段階計画ワークフロー。

## 概要

| 項目 | 内容 |
|------|------|
| 対象ツール | Claude Code / Codex |
| 用途 | 複雑な実装の計画立案（外部レビュー付き） |
| 特徴 | 別セッションによるレビューを経て洗練された計画を作成 |

## ワークフロー

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Director   │ ──▶ │   Planner   │ ──▶ │   Review    │ ──▶ │   改善      │
│ (要求分析)   │     │ (計画立案)   │     │ (外部レビュー) │     │ (計画改善)   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
                                                                   │
                                                                   ▼
                                                          ┌─────────────────┐
                                                          │ 計画書 + 疑義事項 │
                                                          │   をユーザーに提出 │
                                                          └─────────────────┘
```

## フェーズ詳細

### Phase 1: Director（指示役）

**目的:** ユーザーの要求を分析し、明確なゴールを定義する。

**実行内容:**
1. ユーザーの要求を分解・整理
2. 曖昧な点があれば質問して確認
3. ゴールと成功条件を明文化
4. スコープの明確化（やること・やらないこと）

### Phase 2: Planner（計画役）

**目的:** 詳細な実装計画を立案する。

**計画書の内容:**
1. アーキテクチャ概要
2. 変更対象ファイルのリスト
3. 実装ステップ（順序付き、依存関係明記）
4. 各ステップで行う具体的な変更内容
5. リスクと対策
6. テスト戦略

### Phase 3: Review（外部レビュー）

**目的:** 外部ツールによるレビューを取得する。

**レビュー依頼方法:**
```bash
# 別のセッションで shin-reviewer を使用
# Codex は非対話の exec を使う（stdin が terminal でない環境でも動く）
codex exec "/shin-reviewer $(cat ./docs/{topic}/plan.md)"
# Claude は --print で非対話実行。必要なら HOME を writable に向ける
mkdir -p ./.tmp/claude-home
HOME="$PWD/.tmp/claude-home" claude -p "/shin-reviewer $(cat ./docs/{topic}/plan.md)"
```

### Phase 4: 改善（計画の洗練）

**目的:** レビュー結果を受けて計画を改善し、最終版を作成する。

**最終出力:**
- 改善された計画書
- 採用した改善点のリスト
- 疑義事項・要確認リスト
- 採用しなかった提案とその理由

## 使用例

```bash
/shin-planner ユーザー認証機能を追加したい
```

## shin-execute との使い分け

| 状況 | 推奨スキル |
|------|-----------|
| シンプルな機能追加・バグ修正 | shin-execute |
| 複雑なアーキテクチャ変更 | shin-planner |
| リスクの高い変更 | shin-planner |
| 外部の視点が欲しい | shin-planner |
| 迅速に実装したい | shin-execute |
