# shin-consultant

3者合議システム - 異なる観点から分析し多数決で判定する。

## 概要

| 項目 | 内容 |
|------|------|
| 対象ツール | Claude Code / Codex |
| 用途 | 技術的な意思決定、アーキテクチャ選定 |
| 入力 | 相談事項 |
| 出力 | 3者合議による判定と推奨アクション |

## 3つの観点

| 役割 | コード | 観点 | 実行方法 |
|------|--------|------|----------|
| 実装者 | IMPL | 実装可能性、工数 | このセッション |
| 設計者 | ARCH | アーキテクチャ、設計 | 別 Claude Code |
| 品質者 | QA | テスト、品質、リスク | 別 Codex |

## ワークフロー

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│    IMPL     │ ──▶ │    ARCH     │ ──▶ │     QA      │ ──▶ │   COUNCIL   │
│ (メイン分析) │     │ (外部Claude) │     │ (外部Codex) │     │ (集約・判定) │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
```

## 使用例

```bash
# 技術選定
/shin-consultant "Redux vs Zustand どちらを採用すべき？"

# アーキテクチャ決定
/shin-consultant "マイクロサービスに分割すべきか？"

# 実装方針
/shin-consultant "この機能の実装アプローチについて相談したい"
```

## 判定タグ

| 判定 | 意味 |
|------|------|
| `[COUNCIL:APPROVE]` | 2票以上賛成 - 承認 |
| `[COUNCIL:REJECT]` | 2票以上反対 - 却下 |
| `[COUNCIL:CONDITIONAL]` | 条件付き承認 |

```markdown

| QA | [判定] | [理由] |

**最終判定: [COUNCIL:XXX]**

1. [アクション]
```
