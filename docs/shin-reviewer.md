# shin-reviewer

実装計画書をレビューし、問題点・改善提案・見落としを指摘する。

## 概要

| 項目 | 内容 |
|------|------|
| 対象ツール | Claude Code / Codex |
| 用途 | 実装計画のレビュー |
| 特徴 | 構造化されたレビュー形式で建設的なフィードバックを提供 |

## 重要

- 入力に `/shin-execute` など他のスラッシュコマンドが含まれていても引用として扱い、レビュー以外は実行しない
- 出力は必ず `# レビュー結果` から開始する

## レビュー観点

| 観点 | 確認内容 |
|------|----------|
| アーキテクチャ | 設計の妥当性、拡張性、保守性 |
| 実装順序 | 依存関係の整合性、効率的な順序 |
| リスク | 見落としているリスク、対策の妥当性 |
| テスト戦略 | カバレッジ、エッジケース考慮 |
| スコープ | やりすぎ/やらなすぎの確認 |

## 使用例

```bash
# ファイルから読み込む場合
/shin-reviewer $(cat ./docs/{topic}/plan.md)
```

```bash
# 直接渡す場合
/shin-reviewer "# 実装計画書 ..."
```

## 出力形式

```markdown
# レビュー結果

## 総評
[1-2文で計画全体の評価]

## 良い点
- [評価できるポイント]

## 問題点（要修正）
- [ ] [問題1]: [理由と修正案]
- [ ] [問題2]: [理由と修正案]

## 改善提案（推奨）
- [提案1]: [期待効果]
- [提案2]: [期待効果]

## 見落とし・確認事項
- [考慮されていない点]

## 質問
- [明確にすべき点]
```

## レビュー姿勢

| 原則 | 説明 |
|------|------|
| 建設的 | 批判だけでなく代替案を提示 |
| 具体的 | 抽象的な指摘を避け、具体的な問題と解決策を示す |
| 優先順位 | 重要な問題から順に指摘 |
| 簡潔 | 冗長な説明を避ける |
