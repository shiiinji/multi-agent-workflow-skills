# Multi Agent Planner Workflow

計画立案に特化したワークフロー。別セッションによるレビューを経て、洗練された計画書を作成する。

**このワークフローは他のワークフローの起点となる。**

## 全体フロー

```
┌─────────────────────┐
│  planner-workflow   │ ← 今ここ
│  (計画書を出力)      │
└──────────┬──────────┘
           │ 計画書ファイル
           ▼
    ┌──────┴──────┐
    │             │
    ▼             ▼
┌─────────┐  ┌─────────────┐
│   tdd   │  │   execute   │
│(任意)   │  │             │
└─────────┘  └─────────────┘
```

## Workflow

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  Director   │ ──▶ │   Planner   │ ──▶ │   Review    │ ──▶ │   改善      │
│ (要求分析)   │     │ (計画立案)   │     │ (外部レビュー) │     │ (計画改善)   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
                                                                   │
                                                                   ▼
                                                          ┌─────────────────┐
                                                          │ 計画書ファイル出力 │
                                                          └─────────────────┘
```

## Phase 1: Director（指示役）

ユーザーの要求を分析し、明確なゴールを定義する。

**実行内容:**
1. ユーザーの要求を分解・整理
2. 曖昧な点があれば質問して確認
3. ゴールと成功条件を明文化
4. スコープの明確化（やること・やらないこと）

## Phase 2: Planner（計画役）

詳細な実装計画を立てる。

**計画に含める内容:**
1. アーキテクチャ概要
2. 変更対象ファイルのリスト
3. 実装ステップ（順序付き、依存関係明記）
4. 各ステップで行う具体的な変更内容
5. リスクと対策
6. テスト戦略（TDD を使うかどうか）

## Phase 3: Review（外部レビュー）

別セッションで計画をレビューさせる。

**レビュー依頼（両方に実行）:**
```bash
codex "/shin-reviewer $(cat ./docs/{topic}/plan.md)"
claude "/shin-reviewer $(cat ./docs/{topic}/plan.md)"
```

両方のレビュー結果をこのセッションに貼り付けてもらう。

## Phase 4: 改善 & 計画書出力

レビュー結果を受けて計画を改善し、**計画書ファイルを出力**する。

**計画書の保存先:**
```
./docs/{topic}/plan.md
```

**計画書フォーマット（必須）:**
```markdown
# 実装計画書

## メタ情報
- 作成日時: YYYY-MM-DD HH:MM:SS
- 作成者: planner-workflow

## ゴール
[具体的な達成目標]

## 成功条件
- [ ] 条件1
- [ ] 条件2

## スコープ
- やること: [...]
- やらないこと: [...]

---

## アーキテクチャ
[アーキテクチャ概要]

## 実装ステップ

### Step 1: [ステップ名]
- **対象ファイル:** `path/to/file.ts`
- **変更内容:** [具体的な変更]
- **依存:** なし / Step X が先に必要
- **テスト:** 必要 / 不要

### Step 2: [ステップ名]
...

## テスト戦略
- TDD を使用: はい / いいえ
- テスト対象: [...]
- テストフレームワーク: [Vitest / Jest / etc.]

## リスクと対策
| リスク | 対策 |
|--------|------|
| [リスク1] | [対策1] |

---

## レビュー対応
### 採用した改善点
- [改善点]: [どう反映したか]

### 疑義事項・要確認
- [ ] [疑問点]: [背景と選択肢]
```

## 次のステップ案内

計画書出力後、ユーザーに次のステップを案内する:

```markdown
## 計画書を出力しました

📄 `./docs/{topic}/plan.md`

### 次のステップ

**A. TDD で実装する場合（テスト戦略で TDD=はい の場合）:**
\`\`\`bash
/shin-tdd ./docs/{topic}/plan.md
\`\`\`

**B. 直接実装する場合:**
\`\`\`bash
/shin-execute ./docs/{topic}/plan.md
\`\`\`

計画書の内容を確認し、どちらかを選択してください。
```
